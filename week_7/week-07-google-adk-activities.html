    Corte 2 · Week 7 of 16

    Lab & Activities

    Quiz, building a stateful ADK agent from scratch live, a state-scope workshop, an individual extension lab, and peer review.

    How this session runs

    2 hours of theory (content page) + 4 hours of hands-on lab (this page). Today's build is the study_planner_agent — a single ADK agent that uses all three real state scopes — plus its simplified LangChain analog.

    Activity 1 · Warm-up Concept Quiz

    10 minIndividualFormative

    1. Which ADK object actually executes the model-call / tool-call loop for one user turn?

    Correct answer: B. The Runner drives the loop and streams events; SessionService only stores state.

    2. A tool needs to remember a user's preference across completely separate future conversations. Which state key prefix is correct?

    Correct answer: C. user: state is tied to user_id and persists across that user's sessions, not shared with other users.

    3. Why must a tool function's parameters be type-hinted?

    Correct answer: A. Without hints, ADK cannot build a reliable schema, and the model won't know the expected argument types.

    4. Which file is not optional in an adk-web-discoverable agent folder?

    Correct answer: B. __init__.py (plus agent.py with a root_agent) is what adk web scans for.

    Activity 2 · Instructor-Led Live Coding

    40 minWhole group

    Build agents/week-07-google-adk/adk/study_planner_agent/ live, from an empty folder, following Section 4 of the content page. Add the three tools (set_preferred_pace, log_study_session, get_study_summary) one at a time, testing each in adk web before adding the next. Then:

    1. Start a new session with the same user_id and confirm user:preferred_pace survived while session_log reset.
    2. Open langchain/app.py and discuss why its "memory" is a plain Python dict rather than real scoped session state — and why that's an honest simplification, not a framework limitation (LangGraph's checkpointer, Week 9, is the real equivalent).

    Activity 3 · Group Workshop: Pick the Right Scope

    30 minGroups of 3–4

    For each piece of data below, decide: no prefix, user:, app:, or temp: — and justify it in one sentence.

    1. The user's preferred UI language.
    2. A raw API response a tool needs to pass to another tool call two steps later, within the same turn.
    3. The number of currently active free-tier API quota units remaining today, shared by all users of your app.
    4. Which documents the user uploaded in this conversation for RAG (Week 4 recap).

    Compare answers across groups — disagreements are usually a sign the "lifetime" of the data was ambiguous, which is exactly the judgment call this section trains.

    Activity 4 · Individual Lab: Extend the Study Planner

    75 minIndividualGraded (activities)
    • Add a fourth tool, reset_session_log(tool_context), that clears only the session-scoped log without touching user:preferred_pace.
    • Add an app:-scoped counter, app:total_sessions_logged_all_users, incremented by log_study_session.
    • Reproduce both new tools in langchain/app.py's simplified state dict, and add a code comment explaining which real ADK scope each one is standing in for.
    • Commit your finished apps under week-07/ in your course GitHub repository.
