    Quiz, guided coding, a break-the-RAG-system workshop, an individual lab on your own project data, peer review, and the full Corte 1 delivery rubric.

    Activity 1 · Warm-up Concept Quiz

    10 minIndividualFormative

    1. Which two RAG stages run on every single user query (not just once at setup)?

    Correct answer: B. Ingestion/indexing happen once per document; retrieval/generation happen per query.

    2. Why add overlap between chunks in fixed-size chunking?

    Correct answer: A. Overlap trades a little duplication for fewer split-idea failures.

    3. Your assistant confidently answers a question your source documents never mention. What should you check first?

    Correct answer: C. Most "hallucination" bugs in student RAG systems are retrieval bugs.

    4. What's the main practical advantage of ChromaDB over rolling your own FAISS index for a typical class project?

    Correct answer: B. FAISS is a lower-level library; you'd build persistence/metadata yourself.

    Activity 2 · Instructor-Led Live Coding

    45 minWhole group

    Follow along in week-04-rag.ipynb, sections 1–3: chunk a sample document, index it in both ChromaDB and FAISS, and run answer_with_rag live — including on a deliberately out-of-scope question, to see the "I don't have that information" behavior in action.

    Activity 3 · Group Workshop: Break the RAG System

    45 minGroups of 3–4

    Using the instructor's sample RAG system (or your own), each group tries to make it fail in one of these ways:

    1. Ask a question answerable only by combining facts from two different chunks — does n_results need to increase?
    2. Ask an ambiguous question and see whether retrieval grabs the wrong section entirely.
    3. Ask a question with no answer in the documents — confirm it declines instead of guessing.
    4. Propose one concrete fix for whichever failure your group found (bigger n_results? better chunking? a clearer refusal instruction?).

    Report your best "break" and fix to the class — this is the debugging mindset you'll need for your own project.
